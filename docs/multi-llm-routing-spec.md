# 多 LLM 线路配置规格

## 目标

通过同一个 `.env` 为五类 LLM 模块配置独立的 OpenAI 兼容线路，并提供一条全局备用线路。某模块的主线路缺少配置或在运行中失败后，该模块在本次进程剩余时间内固定使用备用线路；重启后重新尝试主线路。

## 模块

| 配置名 | 使用范围 |
| --- | --- |
| `REQUIREMENTS` | 需求分析、筛选策略 |
| `EVALUATION` | 中间档理由生成、理由重写 |
| `AUDIT` | 审核校对 |
| `PORTFOLIO` | 投放组合规划、重新定价 |
| `ADVICE` | 内容建议 |
| `BACKUP` | 上述任一模块失败后的全局备用线路 |

## 配置契约

每条线路使用以下变量，其中 `{NAME}` 为上表配置名：

```dotenv
LLM_{NAME}_API_KEY=
LLM_{NAME}_BASE_URL=
LLM_{NAME}_MODEL=
LLM_{NAME}_TIMEOUT_SECONDS=120
LLM_{NAME}_STREAM=false
```

所有线路继续共用 `LLM_TRUST_ENV`。主线路任一必填值缺失、超时值无效或流式开关无效时，该模块启动即使用备用线路。备用线路配置不完整或无效时，程序启动失败并指出具体变量，不输出密钥。

## 失败与熔断

- 连接、超时、鉴权、限流、HTTP 服务错误、非法 JSON 和模块输出格式错误均视为线路失败。
- 业务结论（例如审核返回 `reject`）不是线路失败。
- 主线路失败后，当前请求改走备用线路；该模块在当前进程中保持熔断，不再尝试主线路。
- 不同模块的熔断状态相互独立；重启进程后状态清零。
- 备用线路失败时抛出明确错误，不再静默降级。

## 兼容边界

- 保留 `LLMClient.from_env()` 和现有 `build_graph()` 调用方式，供旧脚本与显式注入继续使用。
- CLI 改用六线路注册表。
- 不创建或修改真实 `.env`，只更新 `.env.example` 与 README。

## 验收标准

1. 六条线路可分别读取 API 地址、密钥、模型、超时和流式配置。
2. 缺失的主线路立即使用备用线路；无效备用配置阻止启动。
3. 任一模块主线路失败后，仅该模块在本次进程内固定使用备用线路。
4. 五类模块分别使用对应客户端，需求分析与筛选策略共用一个客户端。
5. 日志记录模块切换和线路名称，但不记录密钥、提示词或响应正文。
6. 新增聚焦测试通过，原有测试不因接口兼容性新增失败。
